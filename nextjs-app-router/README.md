# Next.js App Router + next-intl

A small Next.js 16 landing page ("Tasklane") localized into French, German and Japanese with `npx babelize translate`.

## What Babelize changed

[See the diff](https://github.com/babelize/examples/commit/d63ae53). In one run it:

- Replaced hardcoded text in `app/page.tsx` and `components/*` with `useTranslations()` calls, including `aria-label` attributes and the client-side signup form
- Wrote `public/locales/{en,fr,de,ja}.json`
- Added `i18n/request.ts`, which picks the language from the `NEXT_LOCALE` cookie, then the browser's `Accept-Language`
- Wrapped the layout in `NextIntlClientProvider` and `next.config.ts` in the next-intl plugin
- Added `next-intl` to `package.json`
- Wrote `.babelize/local/babelize-lock.json`, so the next run only translates new or changed strings

## What we fixed in review

[See the diff](https://github.com/babelize/examples/commit/348eb7d):

- **Build error.** `create-next-app` 16.4 turns on `cacheComponents`, and reading cookies and headers then has to happen inside `<Suspense>`. The setup generated by @babelize/cli 1.3.9 didn't do that, so `next build` failed. The layout now wraps the provider in `<Suspense>`, which is what @babelize/cli 1.3.10 and later generate on their own.
- **Brand name.** "Tasklane" was translated (into "pour les enfants" in French). It's plain text again.
- **Plural.** `dueToday === 1 ? ... : ...` became two keys. It's now one ICU message: `{count, plural, one {# task is due today} other {# tasks are due today}}`.
- **Page title and description** in `metadata` weren't extracted. They now come from `generateMetadata`.
- **Translations.** Corrected in all three languages. See [About the translations](../README.md#about-the-translations).

## Run it

```bash
npm install
npm run dev
```

Open http://localhost:3000 and switch your browser language, or set a `NEXT_LOCALE=ja` cookie.
